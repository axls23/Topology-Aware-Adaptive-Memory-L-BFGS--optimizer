Project OverviewTraditional hyperparameter optimization (HPO) techniques such as Grid Search and Random Search are highly inefficient, acting blindly to the curvature of the validation loss landscape. While Bayesian Optimization (BO) improves sample efficiency, it struggles to scale in higher-dimensional continuous spaces. This project proposes a novel application of the Broyden–Fletcher–Goldfarb–Shanno (L-BFGS) algorithm to continuously optimize hyperparameters (e.g., learning rate, weight decay, LoRA rank/alpha) by formulating HPO as a bilevel optimization problem.To address standard L-BFGS's critical vulnerabilities—specifically its tendency to get trapped in saddle points and the prohibitive memory cost of maintaining a global memory window for massive LLM parameters—this project introduces a Layerwise Topology-Aware Adaptive-Memory L-BFGS (Layerwise ta-LBFGS) mechanism. By applying a layerwise independence approximation where the inverse Hessian is approximated as block-diagonal, with each block corresponding to a specific layer, this custom optimizer will maintain isolated, tiny memory buffers ($m$) for the specific hyperparameters of each transformer layer. The memory window expands or contracts based strictly on the condition number of that specific layer, avoiding cross-layer computation while preserving essential geometry.2. Core ObjectivesDevelop a Custom Bilevel Optimizer: Implement an outer-loop meta-learner using L-BFGS to optimize continuous hyperparameters and an inner-loop to train the network weights.Implement Hypergradient Computation: Utilize the Implicit Function Theorem (IFT) alongside Conjugate Gradient (CG) or Neumann series approximations to compute the gradient of the validation loss with respect to the hyperparameters.Novel Algorithmic Contribution (Originality Focus):Block-Diagonal Layerwise Memory: Formulate a decoupled, block-diagonal L-BFGS memory update. The dynamic memory parameter $m_l$ for a given layer $l$ will scale proportionally with the estimated local condition number of that specific layer's landscape, maintaining small buffers (e.g., $m=3$) to preserve memory.Saddle-Point Evasion: Design a heuristic that detects local non-convexity (e.g., via secant condition $y_k^T s_k \le 0$ analysis combined with gradient norm tracking) to actively inject orthogonal perturbations, escaping flat plateaus instead of falsely halting.Benchmarking & Validation: Evaluate the proposed Layerwise ta-LBFGS optimizer on a Large Language Model (e.g., LLaMA-3 8B) using a standard instruction-tuning or language modeling dataset.Performance Target: Demonstrate that the proposed quasi-Newton optimizer avoids premature convergence at saddle points and achieves optimal hyperparameter configurations significantly faster than Bayesian Optimization baselines, while drastically reducing the compute time required by full second-order methods.3. Out of ScopeTo ensure the project remains bounded and achievable within standard academic timeframes, the following are explicitly out of scope:Discrete hyperparameter tuning (e.g., number of layers, number of neurons, activation functions).Computing cross-layer Hessian information; this is intentionally ignored to drastically reduce compute time.Full-parameter fine-tuning of massive architectures (e.g., 70B+ parameter Transformers) where IFT approximations become prohibitively memory-intensive for a single local GPU without PEFT.5. CLI Topology Visualizer SpecificationTo monitor the layerwise topological landscape and the optimizer's state during the optimization runtime and validation inference, a real-time Command Line Interface (CLI) visualizer will be developed using the Rich Python library. This dashboard will provide an intuitive, text-based topological map of the model's layers without the overhead of GUI rendering, making it highly suitable for headless GPU servers.Core Components of the CLI Dashboard:Layerwise Topology Table: A live-updating table displaying the status of each transformer layer block. Columns will include:Layer ID: The specific block being optimized.Condition Number ($\kappa$): The ratio of the largest to smallest eigenvalue of the approximated local Hessian, indicating the ill-conditioning of the layer and dictating the need for adaptive optimization.Memory Window ($m_l$): The current dynamically scaled L-BFGS history size for that layer.Landscape Status: Color-coded textual indicators of the local geometry (e.g., [green]"Convex Bowl"[/green], [yellow]"Narrow Ravine"[/yellow], [red]"Saddle Point"[/red]).Saddle-Point Evasion Logs: A dedicated console log window that triggers timestamped alerts when the secant condition ($y_k^T s_k \le 0$) detects non-convexity, actively recording the orthogonal perturbations injected to escape the plateau.Optimization Progress Bars: Dynamic progress bars tracking the outer-loop meta-iterations and validation loss descent.
